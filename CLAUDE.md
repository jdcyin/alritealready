## Working style
Move fast. Make reasonable calls on implementation details without stopping to ask. Flag and confirm before:
- Major/architectural decisions (choosing the stack, restructuring the project)
- Adding new frameworks or dependencies
- Deleting content
- `git push` or any deploy

## Git conventions
- Work locally. Do not push to GitHub unless explicitly asked.
- Commit messages: concise, explain *why* not *what*.

## Code style baseline
- No unnecessary comments.
- No speculative abstractions or features — build what's needed now.
- Keep things simple until the site's actual needs justify more structure.
